Ciclo de desarrollo v3

Cómo trabajamos desde el funcional hasta producción. Un repo plantilla que se clona, un único artifact por proyecto que acompaña todo el ciclo, y seis etapas: las cinco de siempre más el Setup del entorno.

Guía de comandos: cuándo y cómo se usa cada uno →

OO · Analista · QA decide, define, prueba y aprueba
Desarrollo arquitectura, programación y pruebas automáticas
Claude Code prepara, registra y responde; nunca aprueba ni cierra

Qué cambia respecto de la v2

Las etapas, los roles y el circuito siguen igual. Esto es lo nuevo; en el resto de la página aparece marcado v3.

  1. Un solo artifact por proyecto. Nace con el funcional y crece con cada etapa. Cada entrega es una pestaña nueva del mismo artifact.
  2. Camino de urgencia. Si producción se rompe, se arregla desde main sin tocar la entrega abierta.
  3. Decisiones con aprobación explícita. Las difíciles de revertir no se aceptan por silencio.
  4. Producción con versión y vuelta atrás. Cada salida lleva un tag; si la prueba de humo falla, se vuelve al anterior.
  5. Entrega bloqueada. Si algo impide seguir probando, se cierra con observaciones y lo no probado pasa a la siguiente.
  6. El backlog se ordena al cerrar. En la misma pasada del cierre, el OO da destino a los pedidos nuevos.
  7. El repo guarda un espejo. Al cerrar cada entrega, Claude Code copia observaciones, decisiones y estados a docs/estado/.
  8. Etapa de Setup. Entre la arquitectura y el plan: repo remoto, dependencias y los tres ambientes andando antes de construir.
  9. Las reglas las aplica la herramienta. Claude Code no puede tocar main sin tu confirmación, y la rama está protegida en GitHub.

Cómo arranca un proyecto v3

Tres pasos desde cero. A partir de ahí, todo pasa en el artifact.

1 · Clonar

Se clona el repo plantilla. Trae CLAUDE.md, las convenciones, las plantillas y los comandos. No trae stack: eso se decide en la etapa 3.

git clone https://github.com/cdruizdiaz/metodologia_desarrollo.git mi-proyecto

Cambiá mi-proyecto por el nombre de la carpeta del proyecto nuevo.

2 · Iniciar

En Claude Code se corre /iniciar-proyecto. Pregunta el nombre y quién cumple cada rol, crea el artifact del proyecto y guarda su enlace en el repo.

3 · Funcional

El artifact nace con Inicio y Definición, abierto en la etapa 1. El Analista escribe el funcional ahí, con ayuda de Claude Code, y el OO lo aprueba con una casilla.

Las seis etapas

Cada etapa arranca cuando se aprueba la anterior. Lo que se decide durante la construcción vuelve al funcional.

El circuito de una entrega

Una fase es qué se construye; una entrega es lo que hay para probar ahora. Cada columna es un ambiente.

Observación, comentario y decisión

Una observación genera trabajo y lleva número; un comentario no. Una decisión cambia cómo es el producto y siempre queda escrita en el funcional.

Tipo de observación: Error (test primero, después el arreglo) · Cambio (se registra una DEC) · Duda (no se inventa: se pregunta). Gravedad: Bloquea · Normal · Menor.

Aprobación explícita v3 la llevan las decisiones que cuestan caro de revertir: modelo de datos, plata, seguridad y permisos, y borrado de datos. La marca la pone Desarrollo al registrar la decisión.

Reglas que no se negocian

  1. Solo personas aprueban. Claude Code nunca aprueba una etapa ni una fase, nunca cierra una entrega ni una observación, y nunca pasa a producción algo sin aprobar. La herramienta se lo impide.
  2. Una entrega abierta a la vez. Revisión no se toca mientras está abierta; un cambio nuevo va en la siguiente. La única excepción es una urgencia, y va por su propio camino.
  3. Una entrega cerrada no se reabre. Lo pendiente y lo no probado pasan a la próxima.
  4. Cada paso se entiende solo. Qué se vio, qué cambió, dónde arrancar y qué esperar. Los números son referencia, no explicación.
  5. El guion trae solo lo que la máquina no puede probar.
  6. Toda decisión va al funcional en el mismo commit. Las de Desarrollo se validan en la entrega siguiente; las difíciles de revertir, con aprobación explícita.
  7. Error significa test primero. Primero una prueba que falla, después el arreglo. También en una urgencia.
  8. Toda salida a producción lleva tag. Si la prueba de humo falla, se vuelve al tag anterior y se abre una observación.
  9. Sin burocracia. Quien tiene varios roles hace una sola pasada, y las excepciones se anotan en vez de prohibirse.
